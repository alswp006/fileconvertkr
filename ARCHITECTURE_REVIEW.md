# Architecture Review
Generated: 2026-10-06T17:12:55.147Z
Score: 58/100

## Summary
The codebase has a sensible top-level layout: pages, components, hooks and lib, with feature subfolders for result and history, and lazy dynamic imports for the heavy PDF/HEIC libraries. Structural quality is held back by heavy copy-paste of small helpers (haptics, toast state, filename utilities), a large amount of unused scaffold code (contract.ts, useConversionRunner, TossPurchase, CountUp) that diverges from the real implementation, and inconsistent patterns for PDF error handling, navigation and storage. No true circular dependencies were found, but a few import structures are fragile.
